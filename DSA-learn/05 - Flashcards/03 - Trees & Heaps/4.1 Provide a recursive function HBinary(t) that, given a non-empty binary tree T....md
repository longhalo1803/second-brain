### Q: 📝 4.1 Provide a recursive function `H_Binary(t)` that, given a non-empty **binary** tree $T$ (nodes with fields `key`, `left`, `right`), computes the **height of the tree**. Specify base cases, recursive cases, and the main function for handling an empty tree.

📌 Note:

- The tree is binary and implemented with nodes containing:
  _- key field_ to store an optional value (which is not needed in this exercise);
  _- left field_ that stores the pointer to the left child, if present;
  _- right field_ that stores the pointer to the right child, if present.
- The tree is ordered (i.e., children are ordered from left to right), with no constraint on the number of children of internal nodes, and implemented with nodes that have the following fields: a key field to store an optional value (not needed in this exercise); a firstchild field that stores the pointer to the leftmost child (the first in the ordering); a nextsibling field that stores a pointer to the next sibling. #card
  ?
  **Base case: **the tree consists of a single node / leaf (`t.left = NIL` and `t.right = NIL`): returns $0$.
  **Recursive case****: **the tree has at least one child: recursively computes the height of non-empty subtrees, takes their maximum, adds $1$, and returns the result.

**Pseudocode:**

```text
H_Binary(t)
    if t.left = NIL AND t.right = NIL then return 0
    if t.left = NIL then return 1 + H_Binary(t.right)
    if t.right = NIL then return 1 + H_Binary(t.left)
    return 1 + {H_Binary(t.left), H_Binary(t.right)}
```

📌 Note:
In this case we assume that the tree T is not empty. In fact, checks such as `t.left = NIL` would cause an error, since it is not possible to look up a field in a null node.
If one does not want to include the check `t = NIL` in the recursive function, but still wants to handle the case where `T` (the parameter on which the main call is invoked) is empty, a wrapper function can be used:

```text
TreeHeight_Binary(T)
    if T = NIL then return {-1}
    else return H_Binary(T)
```

*Alternative: ***Base case**: the tree is empty, we return $-1$ (in this way a leaf has height zero).
**Recursive case**: the tree is not empty: we return $1$ plus the maximum of the heights of the two subtrees (works even if one of the two, or both, is empty).

```text
H_Binary(t)
    if t = NIL then return -1
    else return 1 + {H_Binary(t.left), H_Binary(t.right)}
```

Main call: $\textsf{H_Binary(T)}$.

❓ Question: what would happen if, in the case of an empty tree, we returned zero?
The height would be measured in number of nodes rather than number of edges. Remember that a tree with a single node has height $0$ ($1 + \max(-1, -1) = 0$), not 1.
