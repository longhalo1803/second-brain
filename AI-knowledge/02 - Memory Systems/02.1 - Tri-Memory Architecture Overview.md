## 1. Tại Sao Cần Hệ Thống Bộ Nhớ Ngoại Vi?

Do LLM là hàm toán học không trạng thái (stateless) và Context Window có giới hạn dung lượng và chi phí token, một Agent không thể nhét toàn bộ lịch sử từ trước đến nay vào mỗi lần gọi.

Hệ thống kiến trúc bộ nhớ 3 tầng (**Tri-Memory Architecture**) phân loại thông tin theo đặc tính vòng đời và mục đích sử dụng:

```
                      ┌─────────────────────────────────┐
                      │    WORKING MEMORY / CONTEXT     │
                      │  (Context Window - Ephemeral)   │
                      └───────────────▲─────────────────┘
                                      │
        ┌─────────────────────────────┼─────────────────────────────┐
        │                             │                             │
┌───────┴──────────────┐   ┌──────────┴───────────┐   ┌─────────────┴─────────────┐
│  PROCEDURAL MEMORY   │   │   SEMANTIC MEMORY    │   │      EPISODIC MEMORY      │
│  (Trí nhớ thủ tục)   │   │ (Trí nhớ ngữ nghĩa)  │   │   (Trí nhớ tình tiết)     │
│                      │   │                      │   │                           │
│ - Quy trình, Skill   │   │ - Facts bền vững     │   │ - Chuỗi sự kiện theo TG   │
│ - Markdown files     │   │ - Profile người dùng │   │ - Lịch sử tương tác cũ    │
│ - System instructions│   │ - Vector DB (RAG)    │   │ - SQL DB + Vector DB      │
└──────────────────────┘   └──────────────────────┘   └───────────────────────────┘
```

---

## 2. Bảng So Sánh Chi Tiết 3 Tầng Bộ Nhớ

| Tầng Trí Nhớ | Định Nghĩa | Công Nghệ Lưu Trữ | Cơ Chế Nạp / Truy Xuất |
|---|---|---|---|
| **Procedural Memory** | Hướng dẫn cách hành động, bộ kỹ năng (`SKILL.md`), định dạng output, quy tắc an toàn. | Markdown Files, Local Config, Git Repo | Inject tĩnh hoặc nạp động theo trigger vào System Prompt. |
| **Semantic Memory** | Tri thức bền vững về con người, quy định, chính sách, kiến thức domain (Durable Facts). | Vector Database (Pinecone, Qdrant, Chroma) | Semantic RAG (Top-K Cosine Similarity Search). |
| **Episodic Memory** | Nhật ký các sự kiện, các cuộc trò chuyện đã diễn ra theo dòng thời gian (Time-series logs). | Relational DB (PostgreSQL / SQLite) + Vector DB | Hybrid: SQL lọc theo thời gian/ID + RAG lọc theo ngữ cảnh. |

---

## 3. Vòng Đời Cập Nhật Bộ Nhớ (Memory Lifecycle)

1. **Giai đoạn Thu thập (Write)**: Mọi tin nhắn và kết quả Tool Call được lưu vào Episodic Memory (SQL Database).
2. **Giai đoạn Tinh chế (Distillation)**: Sau mỗi chu kỳ (ví dụ $N$ lượt chat), một **Summarizer Agent** nén dữ liệu từ Episodic Memory thành các Facts cô đọng nạp vào Semantic Memory.
3. **Giai đoạn Đọc (Read / Retrieve)**: Khi có câu hỏi mới, Agent Harness chỉ truy xuất các mảnh thông tin liên quan nhất nạp vào Context RAM.
