## 1. Single Run vs Agent Loop

```
┌────────────────────────────────────────────────────────────┐
│ 1. SINGLE AGENT RUN (1-shot Turn)                          │
│ User Prompt ──► Context RAM ──► LLM ──► Text Response      │
└────────────────────────────────────────────────────────────┘

┌────────────────────────────────────────────────────────────┐
│ 2. AGENTIC LOOP (Multi-step Tool Calling)                  │
│                                                            │
│ User Task (Phức tạp / Đa bước)                             │
│    │                                                       │
│    ▼                                                       │
│ ┌────────────────────────────────────────────────────────┐ │
│ │                  RE-ACT PLANNING CYCLE                 │ │
│ │                                                        │ │
│ │   ┌───────────┐        ┌──────────────┐                │ │
│ │   │  Thought  ├───────►│  Action      │                │ │
│ │   │ (Suy nghĩ)│        │ (Gọi Tool)   │                │ │
│ │   └─────▲─────┘        └──────┬───────┘                │ │
│ │         │                     │                        │ │
│ │         │                     ▼                        │ │
│ │   ┌─────┴─────┐        ┌──────────────┐                │ │
│ │   │ Next Step │◄───────┤ Observation  │                │ │
│ │   │ (Đánh giá)│        │ (Kết quả trả)│                │ │
│ │   └───────────┘        └──────────────┘                │ │
│ └────────────────────────────────────────────────────────┘ │
│    │ (Khi đã thu thập đủ dữ liệu)                          │
│    ▼                                                       │
│ Final Response to User                                     │
└────────────────────────────────────────────────────────────┘
```

## 2. Kỹ Thuật Tool Calling Chuẩn (Function Calling Protocol)

Khi LLM quyết định gọi công cụ, nó không trả về text tự nhiên mà trả về cấu trúc JSON đặc biệt (`tool_calls`):

```json
{
  "role": "assistant",
  "content": null,
  "tool_calls": [
    {
      "id": "call_98231",
      "type": "function",
      "function": {
        "name": "check_crm_customer_status",
        "arguments": "{\"user_id\": \"usr_8812\", \"include_history\": true}"
      }
    }
  ]
}
```

Harness thực hiện:
1. Parse JSON và kiểm tra schema arguments.
2. Thực thi hàm Python/TypeScript tương ứng (gọi API CRM).
3. Đóng gói kết quả thành message có `role: "tool"` và `tool_call_id: "call_98231"`.
4. Gửi lại vào Context RAM để LLM thực hiện vòng lặp tiếp theo.

## 3. Các Mô Hình Loop Phổ Biến

1. **ReAct (Reason + Act)**: Đan xen giữa một bước suy nghĩ và một bước gọi công cụ. Phù hợp cho bài toán tìm kiếm, khám phá.
2. **Plan-and-Solve**: LLM lập toàn bộ kế hoạch 5 bước trước, sau đó thực thi tuần tự hoặc song song từng bước. Phù hợp cho tác vụ kỹ thuật lớn.
3. **Reflection & Self-Correction**: Agent tự sinh code $\to$ Chạy Unit Test $\to$ Nếu Test lỗi, tự đọc traceback và sửa lại cho đến khi Pass.
