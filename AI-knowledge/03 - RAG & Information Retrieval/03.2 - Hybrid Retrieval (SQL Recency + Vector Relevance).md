## 1. Điểm Yếu Của Pure Vector Search

Pure Vector Search (Chỉ dùng khoảng cách Cosine) gặp thất bại nghiêm trọng trong các trường hợp thực tế:
1. **Truy vấn theo thời gian thực (Recency)**: "Cuộc họp diễn ra *hôm qua* nói gì?" $\to$ Vector search không hiểu cấu trúc timestamp, có thể trả về cuộc họp năm ngoái có cùng chủ đề.
2. **Lọc chính xác (Exact Filtering)**: "Tìm hợp đồng của khách hàng có `user_id = 9912`" $\to$ Vector search mang tính xấp xỉ, dễ nhầm với khách hàng `9913`.
3. **Từ khóa hiếm (Exact Keywords / SKUs)**: "Mã lỗi `ERR_502_BAD_GATEWAY`" $\to$ Embedding model làm mờ mã lỗi thành khái niệm chung chung.

## 3. Triển Khai Trong PostgreSQL + pgvector

```sql
-- Truy vấn kết hợp lọc cứng SQL + Xếp hạng theo Vector Cosine
SELECT 
    id, 
    content, 
    created_at,
    1 - (embedding <=> $query_vector) AS similarity_score
FROM episodic_logs
WHERE user_id = $user_id
  AND created_at >= NOW() - INTERVAL '7 days'
ORDER BY similarity_score DESC
LIMIT 5;
```

## 4. Reciprocal Rank Fusion (RRF)

Khi kết hợp kết quả từ BM25 (Full-text keyword search) và Vector Search (Dense search), ta dùng thuật toán **RRF** để tổng hợp điểm:

$$\text{RRF Score}(d) = \sum_{m \in M} \frac{1}{k + r_m(d)}$$

- $M$: Tập hợp các bộ tìm kiếm (Keyword Search + Vector Search).
- $r_m(d)$: Thứ hạng của tài liệu $d$ trong bộ tìm kiếm $m$.
- $k$: Hằng số làm mượt (thường chọn $k = 60$).
